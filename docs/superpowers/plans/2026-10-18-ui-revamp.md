# UI Revamp & Direct Content Sourcing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repaint `UI/frontend`'s theme from the current navy/neon-green to an OffSec-inspired violet/cyan-on-near-black palette, and switch lesson content loading from a drifted duplicate (`UI/frontend/src/content`) to reading markdown and images directly from the repo-root topic folders.

**Architecture:** No framework or dependency changes. `src/utils/markdownloader.js`'s `import.meta.glob` calls are repointed from `../content/<category>/*.md` to `../../../../<repo-root-folder>/*.md` (4 levels up from `UI/frontend/src/utils`), gaining 3 new categories and a per-category image map. `LessonTemplate.jsx`'s image URL rewrite switches from a flat basename lookup against a hand-copied `public/imgs/` to resolving each lesson's own image map. CSS repaint touches `index.css`, `App.css`, and the three component stylesheets, repointing existing custom-property values (not renaming them, except where a genuinely new token — a secondary/cyan accent — doesn't exist yet).

**Tech Stack:** React 19, Vite 7, react-markdown, gray-matter. No test runner is configured in this project (`package.json` has no `vitest`/`jest`); verification throughout this plan is `npm run build` for compile correctness plus the built-in browser tool (dev server + console/DOM checks) for content and visual correctness — the same verification style the existing code already leans on (`markdownloader.js` already self-reports via `console.log`).

**Spec:** [docs/superpowers/specs/2026-10-18-ui-revamp-design.md](../specs/2026-10-18-ui-revamp-design.md)

## Global Constraints

- Repo-root topic folders are reached from `UI/frontend/src/utils/markdownloader.js` via exactly `../../../../<folder>` (verified: 4 levels up lands on `/Users/akd/Github/hacking-tutorial`).
- `FMEA Fundamentals` has a literal space in its folder name — it's a normal JS string in `import.meta.glob`, not a shell arg, so no escaping is needed, just don't forget the space.
- Lesson markdown extension matching must accept both `.md` and `.MD` (root `intro-to-binary-exploitation/Intro.MD` is uppercase; the current glob silently misses it on case-sensitive filesystems like Vercel's Linux build).
- `cli-editors-tutorials` lesson content lives one level down (`emacs/NOVICE.md`); its top-level `README.md` is folder documentation and must NOT appear as a lesson.
- Keep existing CSS custom-property **names** (`--accent-green`, `--accent-green-light`, `--accent-green-dark`, `--bg-primary`, etc.) and only repoint their **values** to the OffSec palette — add new names only for concepts that don't exist yet (the cyan secondary accent). Renaming 66 existing usages across 6 files for naming hygiene is out of scope.
- OffSec reference tokens (from the design spec): background `#1c1822`, primary accent `#6619D0`, secondary accent `#00BFCB`, highlight text `#B183F0`, font Inter, heading weight 600, pill buttons (`border-radius: 9999px`) for primary CTAs.
- `sql-injection-lab`, `hack-ui`, and `docs/` are explicitly out of scope — do not wire them into the lesson loader.

## Review Focus

- A markdown file whose image reference can't be resolved in its own folder's image map (typo, moved file) — should render a normal broken-image box, not throw and blank the whole lesson page.
- `FMEA Fundamentals` (space in folder name) — its lessons must actually appear in `getAllLessons()`, not silently vanish from a malformed glob string.
- `cli-editors-tutorials/README.md` — must be excluded from the lesson list even though it sits next to `emacs/NOVICE.md` inside a category the loader now recurses into.
- `intro-to-binary-exploitation/Intro.MD` (uppercase extension) — must appear in `getAllLessons()`; this already silently failed before this plan touched the glob and is worth pinning now.
- After the CSS repaint, no leftover hardcoded old-theme hex values (`#00ff88`, `#00cc6a`, `#0b1220`, etc.) outside of `index.css`'s own variable definitions — a partial repaint would leave old neon-green colors bleeding through in some component.

### Task 2: Per-lesson image resolution in `LessonTemplate.jsx`

**Files:**
- Modify: `UI/frontend/src/components/LessonTemplate.jsx:57-67` (`transformMarkdownUrl`)

**Interfaces:**
- Consumes: `getLessonImages(lesson)` from Task 1, returning `Record<relativePath, assetUrl>`.
- No change to `LessonTemplate`'s own props (`{ lesson }`) or exports.

- [ ] **Step 1: Replace the flat `/imgs/`-basename rewrite with a per-lesson lookup**

  Compute `const lessonImages = getLessonImages(lesson);` once per render (after the early-return guards, alongside `prevLesson`/`nextLesson`). Rewrite `transformMarkdownUrl` to strip a leading `./` or `../` from the markdown's image `url`, look up the remainder in `lessonImages`, and return the matched asset URL if found:

  ```js
  const transformMarkdownUrl = (url, key, node) => {
    if (typeof url !== 'string') return url;
    const isImageNode = node?.tagName === 'img';
    if (isImageNode) {
      const normalized = url.replace(/^(\.\.?\/)+/, '');
      if (lessonImages[normalized]) return lessonImages[normalized];
    }
    return url;
  };
  ```

  An unresolved image path falls through unchanged (renders as a normal broken-image box — Review Focus item; no try/catch needed since this is a plain lookup-or-fallthrough, not something that can throw).

- [ ] **Step 2: Verify via dev server**

  Using the same dev server from Task 1 Step 8, open a lesson known to reference an image (e.g. an `ethical-hacking` lesson that embeds a screenshot, and a `python-scripts` lesson that uses `images/<file>.png`).
  Expected: both images render (use `read_page` or a screenshot) — confirms the per-category image map resolves paths at two different nesting depths (flat `image.png` and `images/sub.png`).

- [ ] **Step 3: Commit**

